# QA Report - 2026-01-24

## Summary

Full app review covering auth flows, CRUD operations, error/loading/empty states, navigation, data integrity, type safety, UX consistency, and platform behavior.

**Verdict**: App is functional but has several mutation error handling gaps that could cause silent failures in production.

---

## Critical Bugs

| # | Location | Issue | Impact |
|---|----------|-------|--------|
| 1 | `entry/[id].tsx` | Unhandled promise rejections in Alert callbacks — `mutateAsync()` in complete/delete without try-catch | User gets no feedback if operation fails |
| 2 | `subject/[id].tsx` | Silent error swallowing — catch block only comments "Error handled by mutation" | Entry creation can fail silently |
| 3 | `(tabs)/index.tsx` | `hardDelete.mutate()` called without checking `isPending` — user can spam delete | Duplicate deletion attempts, race conditions |
| 4 | `subject/[id].tsx` | Same mutation state issue for delete button in header | Multiple concurrent delete requests |
| 5 | `packages/shared/src/api/items.ts` | `reorderItems()` uses `Promise.all()` without transaction — partial failure leaves inconsistent positions | Item ordering corruption on network errors |

## Non-Critical Bugs

| # | Location | Issue | Impact |
|---|----------|-------|--------|
| 1 | `signup.tsx` line 62 | `as any` type assertion for route pathname | TypeScript safety breach |
| 2 | `signup-success.tsx` | `setTimeout()` inside callback doesn't cancel on unmount | Minor memory leak |
| 3 | `entries.ts` lines 143-144 | Type assertion `unknown as ItemWithRelations[]` without validation | May pass malformed data |
| 4 | `subjects.ts` lines 163-164 | Type casting in aggregation without structure verification | Stats may be incorrect |
| 5 | `useSubjects.ts` | Throws generic `Error('Not authenticated')` instead of `AppError` | Error handler won't categorize correctly |

## Recommended Stories (for Product)

### Must Fix (blocks release)
- **Fix 1**: Add proper error handling + loading states to all mutations (entry complete/delete, subject delete)
- **Fix 2**: Add error state handling to entry detail screen (not just loading)
- **Fix 3**: Enforce email verification before app access

### Should Fix (before beta)
- **Fix 4**: Replace hardcoded domain ID with dynamic fetch
- **Fix 5**: Fix cache staleness in AddItemModal item count
- **Fix 6**: Add transaction pattern for reorderItems

### Nice to Have (post-MVP)
- Optimistic locking for concurrent updates
- RPC for subject stats aggregation
- Retry buttons for network errors
- Color-coded metric comparison
